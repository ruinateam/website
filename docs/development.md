# Разработка и обслуживание

## Runtime и инструменты

Nuxt CLI, `vue-tsc` и статический preview запускаются явно через Bun, без выбора Node по shebang.
Форматирование встроено в Bun; настройки находятся в `bunfig.toml`, интеграция с Zed — в `.zed/settings.json`.
Встроенного линтера в используемой версии Bun нет: `bun lint` вызывает скрипт Oxlint с `.oxlintrc.json`.

Версии пакетов фиксируются в `package.json` и `bun.lock`. После изменения зависимостей проверьте:

```sh
bun install --frozen-lockfile
bun fmt --check
bun run test
bun audit
```

`bun audit --production` не заменяет полный audit. Не обходите несовместимые диапазоны зависимостей
принудительными overrides без проверки потребителей. Three.js и `@types/three` обновляются согласованно
с моделью `skinview3d` и браузерными проверками галереи.

## Данные рейтинга чата

- `NUXT_PUBLIC_SUPABASE_URL` и `NUXT_PUBLIC_SUPABASE_ANON_KEY` задаются через `.env`, в CI — через secrets.
- `NUXT_PUBLIC_` означает доступность значения в клиенте. Не помещайте туда приватные ключи.
- `TIERS_CHANNELS` — список каналов через запятую для `bun run fetch:data`; по умолчанию `zakvielchannel`.
- Supabase хранит снимки в таблице `tiers_snapshots`.
- Роли загружаются с `https://tools.2807.eu/api/getmods/:channel` и `/getvips/:channel`.
- `scripts/fetch-data.ts` записывает JSON в `public/api-cache/tiers/` и `public/api-cache/roles/`.

В GitHub Pages нет работающего Nuxt-сервера. Код из `server/` относится к dev/server-окружению;
статический сайт обращается к подготовленным файлам или внешним сервисам.
Проверка сборки не проверяет доступность внешних API; обновление кэша запускается отдельно.

## Контент и ресурсы

Руководства находятся в `content/guides/`. Схема коллекции задана в `content.config.ts`,
Markdown отображается через `pages/guides/[...slug].vue` и `components/content/`.
При добавлении маршрута проверьте его генерацию: список маршрутов и обход ссылок настроены в `nuxt.config.ts`.

Сохраняйте происхождение и лицензии рядом с ресурсами. Исходные анимации и тестовые fixtures
не считаются мусором только потому, что не используются текущим экраном.
Временные скриншоты и отчёты храните вне исходников либо в игнорируемых каталогах.

## Очистка и публикация

`bun run clean` удаляет только `dist/`, `.output/`, `.cache/nuxt/` и `.nuxt/` относительно корня проекта.
Сначала каталог переименовывается, затем удаляется с ограниченными повторами для файловых блокировок.
Ошибка очистки завершает команду ненулевым кодом, чтобы сборка не продолжалась со старым выходом.
Исходники и `public/api-cache/` эта команда не очищает.

После пересборки перезапускайте `bun run preview`: статический сервер кэширует список файлов.
Старый процесс может отдавать HTML и отсутствующие JS-чанки из разных сборок.

[Workflow публикации](../.github/workflows/deploy.yml) устанавливает зависимости по lockfile,
проверяет обязательные параметры Supabase, обновляет кэш, выполняет `bun run build`
и публикует содержимое `dist/public` в GitHub Pages.

Для изменений интерфейса дополнительно проверяйте реальные desktop/mobile-кадры, клавиатуру,
reduced-motion и fallback-состояния. Указывайте пропущенные проверки и ограничения окружения;
не сохраняйте в постоянной документации устаревающие числа тестов и адреса временных preview-серверов.
